## 1. 이미지 모드 (사진 채점)

**✅ 이미 된 것** — 전처리(**측지 재구성 + 연한글씨 보존 라우팅, 2026-07-27~31**), 글자 탐지(CRAFT pretrained,
**새 파이프라인 F1@0.3 0.891 검증**), 크기·기울기(문장 기울기)·자간·행간·기준선 **5지표** 채점, 종합점수(교육 가중
3:2:1), 명료도 경고화, 절대 규범 축.

- **✅ 전처리 개편(2026-07-27, 상세: [DEVLOG.md](DEVLOG.md) 11막 / [IMAGE_PIPELINE_REBUILD_PLAN.md](IMAGE_PIPELINE_REBUILD_PLAN.md))** —
  adaptiveThreshold → **채널 max + 조명 정규화 + 측지 재구성**(비침·괘선 원천 제거). 확정 사항:
  - **리사이즈 = A방향(풀해상도 유지, 다운스케일 없음)**. 장축<800만 업스케일. ⚠️ 8막의 "리사이즈 유지(다운스케일)가
    정답"은 **뒤집혔다** — 그때 C(축소)가 나아 보였던 건 close 버그로 획이 깨진 상태였기 때문이고, close를
    고치니 A(풀해상도)와 탐지 동률이면서 원본 충실도가 높아 A 채택. glyph-aware(B)는 data/에서 열세라 미채택.
  - **close 버그 수정** — `CLOSE(fg)`(배경 close, 획 43% 소실) → `255-CLOSE(255-fg,2×2)`(잉크 전경 close).
  - **보존율 게이트 = coverage 방식**(percentile→coverage) — 연한 획 복구, 비침 이미지엔 recon 유지.
  - **탐지 크래시(T2) 수정** — `get_prediction(poly=False)`로 풀해상도 폴리곤 크래시 제거.
  - 단위 테스트 32개 통과. 유지 지표(크기·정렬·기울기)는 CV·각도라 **스케일 불변** — 리사이즈가 채점을 왜곡 안 함(실측).
- **✅ 연한 글씨 손실 수정(2026-07-30, 커밋 1fc09cb)** — 측지 재구성이 seed 없는 연한 획을 비침처럼 지우던
  버그(test7·test5·data/). **이미지별 라우팅** 도입: near-black 진짜 잉크(진한 앵커)가 없으면 gentle(연한 글씨
  보존), 있으면 geodesic(비침 제거). 세기·sharpness로는 연한글씨≡비침 구분 불가라 이미지 단위로 갈랐다(DEVLOG 12막).
- **✅ T4 분석기 정리(커밋 b9d7ed5)** — 획 굵기·글자별 slant 제거, **문장 기울기**(행별 박스 중심선 회귀, 전처리
  좌표 — deskew 역회전 안 함, 사용자 결정) 도입. 채점 5지표(3:2:1).
- **✅ T5·T7 완료(커밋 386c71c)** — 새 파이프라인 기준 GT 재라벨 후 F1 측정. **F1@0.3 0.891 / @0.5 0.820**(12장).
  옛 0.938은 dev=test·다른 이미지셋이라 직접 비교 아님(동급). 오류는 과병합(merge) 우세.
- **⚠️ 미구현**: 비침이 gentle로 통과해 유령 박스가 나오면 **"깨끗한 종이 재촬영" 안내**(탐지/품질 단계) —
  사용자 방침(연한 글씨 손실보다 유령→재촬영이 낫다). 아직 안 만듦.

- **🟡 탐지 정확도 한계 (파라미터로 못 넘는 벽)** — 새 파이프라인 12장 오류는 **과병합(merge 151 vs split 23)이
  지배적**: 붙여쓴/흘림 2음절을 한 박스로(잉크 골짜기 없으면 기하만으론 분리 불가 — "읽어야" 나뉨) / 소형 밀집

  과폭 분할·자소 병합·CC 완성)는 대부분 소진 → 진짜 개선은 **파인튜닝**(§4). 근거: `archive/DETECTION_IMPROVEMENT_PLAN.md`.
- **✅ 평가셋·정답지(GT) — 새 파이프라인 기준 재라벨(2026-07-30~31)** — **12장**: 사진 test·test2·test5·test6·
  test7 + 홀드아웃 test8·test_line1 + **data/ 태블릿 5장**(04384·04423·04424·04425·04449). test4·test3_crop은
  개성 강함으로 배제. gentle 라우팅 이미지는 전처리 출력이 바뀌어 재라벨, geodesic(test2·test8)은 유지.
  **브라우저 라벨링 GUI**(`eval/label_gui.py` → 사람이 클릭 → `label_helper.py build`)로 만든다(AI가 판독 안 함).
  절차·관례는 `gt-labeling` skill. GT 관례: 문장부호·긴 장식획 제외, 영문 글자별 1박스, 작은 획(<40px blob)은
  몸통으로 잡거나 스킵. **data/ 주의**: AI Hub 라벨이 어절 단위라 자동변환 불가·소형 파편이라 라벨 어려움 →
  글씨 크고 깨끗한 5장만(**GT는 측정용이지 학습용 아님** — 평가엔 대표 표본이면 충분). 남은 것: 필요 시 도메인 추가.
- **✅ 후처리 과최적화 — 육안 홀드아웃 확인(2026-07-30)** — 미라벨 홀드아웃(test8·test_line1~3)에 후처리
  on/off 박스를 나란히 렌더(`debug_holdout_postproc.py`)해 눈으로 비교. **후처리가 새 오류를 만들지 않고**(오병합/
  오분할은 OFF·ON 양쪽 공통 = CRAFT 원본에서 옴), **괘선 위 유령 박스 없음**. → 과최적화 우려 육안상 종료.
  이후 T7 정량(F1@0.3 0.891, 홀드아웃 test8·test_line1 포함)이 뒷받침. 판정법(델타 오버레이): DEVLOG 12막.
- **✅ 순환성 편향 측정(2026-07-23, test3_crop)** — 기존 GT(탐지기 초안 기반) vs 독립 재라벨링 GT를
  비교: 두 GT 상호 평균 IoU **0.992**(140쌍, 129쌍은 IoU>0.99), 탐지 F1도 어느 GT로 재든 차이 ≤0.007

## 3. 통합 · 범위

- **🤝 백엔드 통합(실서비스 실질 블로커)** — 어댑터 `backend/app/services/ai_adapters.py` 실구현은 있음.
  남은 것: ① 브랜치 병합(ai-setup 실구현 채택) ② 라우트가 AI 전처리/분석 쓰도록 결정(⚠️ 정확도는
  전부 AI 전처리 전제 — 다른 방식 섞으면 보장 안 됨) ③ bbox "전처리 후" 좌표계 오버레이 합의 ④
  backend `requirements.txt`에 torch 추가. 근거: [HANDOFF.md](HANDOFF.md) §5.1.
  **백엔드 팀원용 인계 가이드 = [BACKEND_INTEGRATION.md](BACKEND_INTEGRATION.md)**(2026-08-01 신설 —
  위 ①~④와 함정 8·자가 검증·팀 결정 목록 종합, 수치 당일 재실측).
- **⚠️ 통합 시 터질 위험 2가지 (통합 전 반드시 합의)** — ②③이 왜 단순 협의가 아니라 위험인지:
  1. **전처리 체인 의존** — 탐지 성능은 특정 체인(**측지 재구성**+deskew+distance transform) 전제다.
     백엔드가 다른 전처리(예: 단순 이진화)를 쓰면 성능은 무보장. 이건 **파인튜닝 2차 실패
     (학습 65개 vs 실제 3개 탐지 — 도메인 불일치)와 정확히 같은 구조**다. 근거: [DEVLOG.md](DEVLOG.md) 3막.
     (리사이즈는 07-27부터 **A방향=다운스케일 없음**이라 "리사이즈 스킵" 위험은 사라짐 — 오히려 풀해상도 유지가 기본.)
  2. **좌표계** — 반환 bbox는 **"전처리 후" 좌표**(deskew 회전 반영, 큰 사진도 다운스케일 없어 배율≈1.0,
     장축<800 입력만 업스케일 배율)로 확정. 프론트가 **원본 사진 위에 그리면 deskew 회전만큼 어긋난다 =
     통합 첫날 터지는 종류**의 버그. 오버레이는 전처리 이미지 위에 그리는 것이 계약.
  - **AI 파트가 준비할 것**: ⓐ 어댑터(`preprocess_image` 드롭인)로 백엔드가 AI 전처리를 그대로 쓰게
    강제 — *구현은 이미 됨, 라우트 반영만 남음* ⓑ 좌표계 계약 명문화(반환 bbox=전처리 후 좌표,
    오버레이=전처리 이미지 위) ⓒ 오버레이용 전처리 이미지를 응답에 함께 반환.
  - 나머지(브랜치 병합·라우트 결정·torch 의존성)는 AI 혼자 못 정함 → 백엔드 트랙 협의.
- **⏸ 범위 밖(청사진)** — 개인화·실시간 영상(YOLO)·OCR 텍스트 변환·자유필기 획순 채점. 이번 범위 =
  두 모드 분석 + 학습 대시보드(SFR-008)까지. 근거: [requirement.md](requirement.md).
