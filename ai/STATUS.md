## 1. 이미지 모드 (사진 채점)

### 🆕 2026-09-02 개편 — 채점 항목 재정의 · 문구 6문장 · 글자 단위 박스 (DEVLOG 32막)

**항목 5개로 고정하고, 화면에 나가는 문장 수를 6개로 못 박았다**(종합 1 + 항목 5).
종전에는 60~84점 구간에 아무 문구도 안 나갔고, 자간·행간은 점수만 재고 문구가 없었다.

| 항목 | 무엇을 재나 | 빨간 박스 |
|---|---|---|
| 크기 균일성 | 글자 크기가 서로 균일한가 (높이 CV) | 다른 글자들 평균에서 벗어난 글자 |
| **기울기 균일성** | 글자 기울기가 서로 균일한가 (각도 σ) | 중앙값에서 ±7° 넘게 벗어난 글자 |
| **줄 정렬** | 행 기준선이 수평인가 **+** 글자가 그 줄에 앉았나 (나쁜 쪽) | 기준선에서 행높이 25% 넘게 벗어난 글자 |
| 자간 | 글자 사이 간격이 서로 균일한가 | — (글자에 귀속되지 않음) |
| 행간 | 줄 사이 간격이 서로 균일한가 | — |

- 항목별 문구 기준은 **80점** — `_band_score`의 '우수' 경계와 일치해 등급과 어긋나지 않는다.
  수치는 넣지 않는다("높이 CV 24.3%"는 사용자에게 뜻이 없다 — 사용자 결정).
- 박스는 **기본 초록**, 위 3항목 중 **하나라도** 미흡하면 빨강(종합 점수 미사용, 캔버스와 같은 규칙).
- **글자를 너무 기울여 쓰는 습관**은 별개 축(`CHAR_SLANT_NORM_DEG = 10°`)으로 문구만 낸다.
  균일성만 보면 전부 똑같이 25° 기울여 쓴 글씨가 만점이기 때문. **박스는 치지 않는다** —
  글씨체 전체의 습관이라 짚을 글자가 없다(사용자 결정).

⚠️ **`slant_consistency_score`는 이름은 그대로인데 의미가 바뀌었다** — 줄 오르내림 → 글자 기울기
균일성. 이름은 오히려 정확해졌지만 **대시보드에 이전에 쌓인 값과는 뜻이 다르다.**
⚠️ `mean_char_slant`는 **DB 컬럼이 없어 저장하지 않는다.** 추이를 보려면 마이그레이션 필요.

## 6. 자주 쓰는 명령 (작업 재개용)

WSL/Linux 기준. Windows 로컬은 `venv/bin/python` 대신 `venv/Scripts/python.exe`.

| 목적 | 명령 |
|---|---|
| 탐지 평가 (merge/split 컬럼 포함) | `ai/venv/bin/python eval/evaluate_detection.py` |
| AI Hub 양식지까지 포함 | 위 명령에 `--aihub` |
| GT 라벨링·검수 | `/gt-labeling` skill 또는 `python eval/label_gui.py <이미지>` → 브라우저에서 묶기 → build |
| E2E 수동 점검 | `ai/venv/bin/python debug_e2e_image_mode.py` |
| pretrained vs 파인튜닝 비교 | 실제 `CraftDetector`로 채점하는 `evaluate_detection.py`로 검증(옛 `debug_compare_production.py`는 2026-07-31 제거, git `ec3f0fb`) |
