## 0. 왜 하는가

- **비침(뒷장 잉크 비침)** 이 이진화에서 진짜 획과 같은 검정으로 승격돼 CRAFT가 유령 박스로 오검출.
  이 유령이 평가 통계(크기 균일성 등)를 오염시킴.
- 지금까지 탐지 후처리(1~14단계)만 손봤고 **전처리는 초기값 그대로**라, 한 번도 검증된 적 없음.
- 홀드아웃(test8~10·test_line)에서 유령·크래시가 실제로 재현됨 → 개발셋 과최적화 우려의 실물 증거.

## 1. 이번에 확정한 결정 (근거 포함)

### 1.1 평가 요소 재설계 (SFR-005I)
- **채택**: ① 크기 균일성 ② 행정렬(자간·행간 포함) ③ **문장 기울기**
- **제거**: 획 굵기 균일성, 글자별 slant
- **문장 기울기 정의**: 사람이 **수평으로 쓰는가 / 올라가며 쓰는가 / 내려가며 쓰는가**(필기 습관).
  글자 자체 기울기가 아니라 **행별 박스 중심선의 기울기**(bbox 좌표만으로 측정).
  → 이 정의상 **deskew 이전 좌표(원본 방향)에서 측정**해야 함(deskew가 그 습관을 지우므로).
- **핵심 파급**: 제거하는 두 지표가 유일하게 **이진 이미지를 읽던** 소비자였음
  (획 굵기=이진 전체 distanceTransform, slant=박스 내 이진 HoughLines).
  → 재편 후 **이진 이미지의 유일한 소비자는 CRAFT 탐지뿐**, 평가는 박스 좌표만 사용.
- 근거: `requirement.md` REQ-005I-1은 원래 "크기·기울기·행정렬 3개"만 요구. 획굵기·자간·행간은
  개발 중 추가된 확장 지표였고, 획굵기는 가중치 최하(1)에 이진 품질에 가장 민감했음.

### 1.2 전처리 (SFR-003I)
- **채택**: dmack 파이프라인 코어 = 채널 max 그레이 + 조명 정규화(division) + **측지 재구성**(비침 제거).
  깔끔히 재작성(보존보다 정확성 — 사용자 방침).
- **유지**: 품질 점수·재촬영(REQ-003I-4), Hough deskew(REQ-003I-3). dmack엔 둘 다 없으므로 앞뒤에 붙임.
- **극단 종횡비**(초광각, 예: test9·test10 ≈ 4.5:1) → **재촬영 요구**로 처리(전처리 단계).
- **폐기**: 이전에 넣은 pixel 게이트(`_suppress_faint_blobs`) — 재구성이 대체.
- 근거: dmack 보존율 우리 13장 99.3~100%, 레이턴시 최악 3.2초(12MP)로 REQ-003I-1(5초) 내.
- **🐛 실행 중 발견·수정(계획에 없던 항목) — close 방향 버그**: 마무리 close를 `CLOSE(fg,3×3)`(검은
  잉크/흰 배경에서 **밝은 배경을 close** → 가는 획 43% 소실)로 넣었던 것을 `255-CLOSE(255-fg,2×2)`
  (잉크 전경 close → 획 연결)로 수정. data/(글자 12px) 재현율 0.38→0.99. dmack `(1)` 버전과 동일한 수정.
- **보존율 게이트 = coverage 방식 확정**: 계획의 "보존율<90%(percentile)" 대신 (1)식 coverage 게이트
  (`cov≥0.97` 또는 `cov≥0.92 & fer≥0.30`, 폴백 stretch lo=90) 채택. 연한 획 복구 + 비침 이미지엔 recon 유지.
  근거: data/ 10장에서 재현율 동률(0.994)이면서 04399 등 연한 글자를 되살림(육안), 합성 비침에서 비침 0px 유지.

### 1.3 문제 범위 (측정으로 좁혀짐)
| 문제 | 실측 | 처리 |
|---|---|---|
| 극단 비율 | 리사이즈가 글자 뭉갬 | **재촬영 요구** |
| 비침 | CRAFT가 텍스트로 오검출 → 유령 박스 | **재구성으로 원천 제거** |
| 괘선(줄노트) | CRAFT가 박스 안 만듦 (측정) | 처리 불필요 |
| 형광펜 | CRAFT가 박스 안 만듦, 글자 정상 (측정) | 처리 불필요 |

## 2. 작업 항목

### T1. `preprocessing/image_preprocessor.py` 재작성
파이프라인 순서:
1. 디코드(BGR) — 한글 경로 안전(`imdecode`)
2. **채널 max 그레이** (형광펜·색 괘선 배경화)
3. **품질 점수** 산출 → 40점 미만 재촬영 (REQ-003I-4)
4. **극단 종횡비 검사** → 임계 초과 시 재촬영 (신규)
5. **측지 재구성** 이진화 (조명 정규화 → 적응형 seed/mask → 팽창 재구성 → 획 강도 정규화
   → **coverage 게이트**(불충분 시 선형 스트레치 폴백) → **잉크 전경 close**(`255-CLOSE(255-fg,2×2)`))
6. **Hough deskew** (±45°, REQ-003I-3)
7. **리사이즈 = A방향(풀해상도 유지)** — ❗계획의 "장축 1600 + 32배수 패딩"에서 **변경**. A/B/C 실측 결과
   close 고친 뒤 풀해상도(A)가 축소본(C)과 탐지 동률 + 원본 충실 → **다운스케일 제거**, 장축<800만 업스케일,
   패딩 없음. (glyph-aware B는 data/에서 열세라 미채택.)
- 소형 노이즈 제거는 리사이즈 뒤 `_remove_small_blobs`로 수행(파이프라인 Step 7).
- 반환: `binary_image`(stroke=255) + 품질·skew·재촬영·필터목록 (기존 `PreprocessResult` 계약 유지)
- 공개 API 시그니처 유지(`preprocess_from_file/bytes/base64`) — 어댑터·디버그 스크립트 호환
- **✅ 반영됨(2026-07-27)**. 단, 재구성 반환은 그레이(stroke bright)이고 하드 이진화는 Step에서 수행.

### T2. `detection/craft_detector.py` 크래시 수정 — ✅ 반영됨(2026-07-27)
- `craft_text_detector`의 `polys` 비균질 배열 → `np.array(polys)`에서 `ValueError`. 우리는 polys 미사용.
- `_craft_prediction`에서 `detect_text` 대신 `get_prediction(..., poly=False)` 직접 호출로 우회.
  박스 결과는 poly 값과 무관하게 동일함을 검증(패치 유무 149자=149자).
- 재현 조건: **풀해상도·고 long_size(2560)**. C(1600)에선 재현 안 되다 A(풀해상도)에서 확실히 터짐 →
  A방향 채택의 전제 조건. 근거: REQ-004I-5(0개 시 graceful 오류)를 크래시가 위반.

### T3. `tests/test_preprocessor.py` 재작성 (TDD)
- 비침 억제(재구성 후 유령 픽셀 미검출), 극단 종횡비 재촬영, 품질 재촬영, deskew, 출력 크기.
- 합성 이미지로 외부 파일 없이 실행(기존 관례 유지).

### T4. `analysis/handwriting_analyzer.py` 정리
- **제거**: `_stroke_width`(획 굵기), 글자별 slant 기반 `tilt_consistency`.
- **추가**: 문장 기울기 = 행별 박스 중심선 선형회귀 기울기(수평/상승/하강 판정 + 일관성).
  **deskew 이전 좌표에서 측정**(§1.1 정의). 구현: 전처리가 `skew_angle`을 반환하므로, 탐지된
  박스 중심을 `+skew_angle`로 역회전해 원본 방향 복원 후 행별 기울기 산출.
- **유지**: 크기 균일성(높이 CV), 행정렬(자간 CV·행간 CV·기준선 이탈).
- 등급·종합점수 가중치 재조정(3지표 체계). 명료도 경고·norm 편차 중 박스 기반만 유지.

### T5. GT 재라벨링 (사람 작업)
- 전처리 좌표계가 바뀌므로 기존 7장 GT 무효 → 새 파이프라인 출력 기준 재라벨.
- 홀드아웃(test8·test_line 등, 초광각 제외) 추가 라벨.
- 절차: `/gt-labeling` skill.

### T6. 비교 시각화 (아티팩트)
- 기존 방식 vs 신규 전처리+탐지 나란히. 기존 렌더는 확보됨(게이트 끈 커밋 베이스라인).

### T7. 검증
- 재라벨 후 `evaluate_detection.py`로 F1 측정, 재편 지표로 종합점수 산출.
- 레이턴시 재확인(REQ-003I-1 5초, REQ-004I-1 500ms).

## 4. 미해결·주의점

- **deskew ↔ 문장 기울기 (해결됨)**: 문장 기울기는 deskew 이전 좌표에서 측정(§1.1·T4). 단, 카메라
  기울기와 필기 기울기는 페이지 기준선 없이는 완전 분리 불가 — 원본 방향 측정값에 카메라 기울기가
  일부 섞일 수 있음(감수). 정면 촬영을 전제로 함.
- **임계값 근거**: 재촬영 종횡비, 재구성 상수(seed 30%·mask 1.6×·보존 90%·획강도 230)는 dmack이
  11장으로 검증. 우리 도메인 재튜닝 여지. 설정 파일화(REQ-004I-3 방침).
- **GT 없이는 최종 F1 미검증**: 지금까지 이득은 시각적으로만 확인. T5 완료 전엔 "더 낫다"가 인상 수준.
- **백엔드 통합**: 좌표계·전처리 어댑터는 이 개편 확정 후 협의(STATUS §3).
