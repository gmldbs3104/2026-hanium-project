# 캔버스 채점 축 재설계 — 설계

- 날짜: 2026-10-08
- 범위: 캔버스 모드(자모음 · 한 글자 · 문장 연습)의 채점 기준, 점수 계산, 채점 거부, 결과 화면, 저장·대시보드
- 상태: 설계 합의 완료 (2026-10-08 대화). 구현 계획은 이 문서를 기준으로 따로 작성한다.

## 1. 배경

2026-09-01부터 09-21까지 사용자 신고에 하나씩 대응하며 채점 항목이 9개(획순·획방향·기울기·모서리·성분비율·크기·자간·위치·모양)까지 늘었다. 각 결정은 이유가 있었지만 전체 설계가 없어서:

- 연습 종류마다 항목 조합이 달라 사용자가 "왜 이 글자엔 이 항목이 있나"를 알 수 없다.
- 같은 성질(형태·쓰는 법·배치)이 서로 다른 이름의 항목으로 나뉘어 한 습관이 여러 항목에 걸린다.
- 같은 이름이 단계마다 다른 뜻이다(낱자의 '기울기'는 글자 전체 기울기를 포함, 음절은 획만).
- 점수 규칙이 겹친다 — 채점 거부 게이트, "틀린 항목 × 20", "절반 넘으면 두 배", 박스는 항목별 OR.
- 문구가 세 곳(AI 교정문, 백엔드 피드백 문구, 프론트 사유 라벨)에서 따로 만들어진다.

## 2. 목표와 원칙

- 연습 단계(자모음 → 한 글자 → 문장)마다 **그 단계가 가르치는 것**을 채점한다. 단계별 기준이 다른 것은 의도다.
- 채점 **축**의 이름은 단계가 올라가도 바뀌지 않는다. 단계는 축을 **더해 갈 뿐**이다.
- 경고가 있는 축은 만점이 될 수 없다 — 경고와 점수는 항상 같은 방향이다(2026-09-17 결정 유지).
- 임계값 숫자는 지금 값을 그대로 쓴다. 보정은 실사용 데이터(`correction_flags`)가 쌓인 뒤 한다.
- 문구는 AI가 만든 사유 문자열 하나만 쓴다.

### 비범위

- 이미지 모드는 건드리지 않는다(요구사항 REQ-005I-4: 캔버스와 로직 공유 금지).
- 임계값 재보정, 자리 그룹핑(획이 옆 칸으로 넘어가는 문제)은 이 설계에 포함하지 않는다.
- 낡은 문서(CLAUDE.md, DATA_FLOW.md 등)의 정정은 별도 작업이다.

## 3. 채점 축

세 가지 성질을 네 축으로 정리한다. 축은 세부 판정의 묶음이다.

| 축 | 세부 판정(1건의 단위) | 흡수되는 기존 항목 | 적용 단계 |
|---|---|---|---|
| 획순 | 순서가 어긋난 획(두 획이 자리를 바꾼 것은 1건 — 어긋난 획 수 ÷ 2, 올림) · 반대로 그은 획 1획 · 획 수가 표준과 다름(1건) | 획순, 획방향, 획 수 | 전부 |
| 모양 | 기울어진 곧은 획 1획 · 글자 전체 기울기(자모음, 1건) · 둥글린 모서리 1곳 · 표준과 다른 모양(자모음, 1건) | 기울기, 글자 기울기, 모서리, 낱자 모양 | 전부 |
| 짜임새 | 크기·비율·자리 중 하나라도 걸린 성분 1개 | 성분비율 | 한 글자 · 문장 |
| 배치 | 크기(1건) · 자간(1건) · 위치(1건) | 크기, 자간, 위치 | 문장 |

단계별 축:

| 단계 | 배우는 것 | 축 |
|---|---|---|
| 자모음 | 획을 바르게 긋기 | 획순 · 모양 |
| 한 글자(받침 글자) | 자모를 짜 맞추기 | 획순 · 모양 · 짜임새 |
| 문장 | 글자를 줄에 놓기 | 획순 · 모양 · 짜임새 · 배치 |

세부 판정의 측정 방법과 임계값은 지금 코드의 것을 그대로 쓴다: 곧은 획 기울기 12°, 글자 전체 기울기 15°, 모서리 비율 0.6, 성분 넓이·비율 ±55%(중성 ×1.3)·중심 26%, 크기 0.70~1.40배(가이드 없으면 중앙값 대비 0.65~1.5), 자간은 가이드 글자 중심 간격 대비 −25%/+80%(가이드 없으면 평균 글자폭의 15%~120%), 위치는 글자 중심이 칸 안에 있는가.

측정할 세부 판정이 하나도 없는 축(예: 곧은 획도 모서리도 없는 음절의 '모양')은 **미측정(None)** 이다. 0점도 만점도 아니며 평균에서 빠진다.

## 4. 점수

- 축 점수: 걸린 세부 판정이 0건이면 **100**, 1건이면 **70**(일부), 2건 이상이면 **40**(심함).
- 글자 점수: 측정된 축의 평균(정수 반올림). 미측정 축은 분모에서 빠진다. 측정된 축이 없으면 None.
- 문장 점수: 글자 점수의 평균(채점 거부로 0점이 된 글자 포함).
- 자모음·한 글자 세션 점수: 그 글자의 점수.
- "틀린 항목 × 20", "절반 넘으면 두 배" 규칙은 없앤다. 가중치도 없다.

## 5. 채점 거부

세 단계 공통이며, 조건은 세 개다.

1. **획이 하나도 없다**(문장에서 건너뛴 칸) → `missing`.
2. **획 수가 표준의 2배 초과** — 명백한 낙서 → `too_many_strokes`.
3. **획 모양이 표준과 다르고, 잉크도 표준 자리에 없다** → `shape_mismatch`. 두 기준을 **둘 다** 넘어야 한다.
   - 획 모양 기준: 획끼리 짝지어 ±35° 회전·역방향을 허용한 거리(평균 0.20 / 최대 0.32, 짝 없는 획은 평균에 0.6 벌점).
   - 잉크 기준: 점구름 비교 어긋남(양방향 95퍼센타일 중 나쁜 쪽) 0.15 초과.

지금의 "획 수가 절반 이하" 조건은 없앤다(획을 이어 쓴 정상 글씨를 거부하던 조건 — 잉크 기준이 대신한다).

> 2026-10-08 구현 중 정정: 처음에는 잉크 기준 하나로 줄이려 했으나, 잉크 기준만 쓰면 ㅣ 하나를 25° 기울인 '리'와 25° 돌려 쓴 ㄱ·ㄴ·ㅁ이 거부됐다. "기울기는 모양 축이 지적할 몫이지 거부할 일이 아니다"(3절)와 모순이라 획 모양 기준을 함께 둔다. 사유 이름도 기존 DB 플래그(`unscorable:shape_mismatch`)와 이어지도록 `shape_mismatch`를 유지한다.

거부의 결과:

- 자모음 · 한 글자: 지금처럼 세션 전체 채점 불가(`overall_score = None`), "다시 써 주세요" 안내.
- 문장: **그 글자만 0점**(`overall_score = 0`, `scorable = false`)으로 넣고 나머지 글자는 정상 채점한다. 글자 박스는 빨강, 사유는 "다시 써 주세요(목표 글자와 다름)". 세션 전체를 채점 불가로 만들던 규칙은 없앤다. (원래 걱정이던 "그 글자만 빼면 평균이 오른다"는 0점으로 넣으면 생기지 않는다.)
- 획이 하나도 배정되지 않은 칸(문장)은 "다시 써 주세요(쓰지 않음)"로, 위와 같이 0점이다.

## 6. 결과 화면

캔버스 위에는 **박스와 ✓/✕ 뱃지만** 그리고, 사유 글자는 모두 우측 패널에 쓴다.

| 단계 | 캔버스 위 | 우측 패널 |
|---|---|---|
| 자모음 | 박스 없음 | 축별 사유: `획순(1획 반대로 그음)`, `모양(모서리 둥글림)` |
| 한 글자 | 성분 박스 3개, 초록/빨강(지금과 같음) | 성분별 사유(지금과 같음), 축 이름만 새 이름 |
| 문장 | **글자 박스, 빨강만**. 거부된 글자도 같은 박스 | 문제 글자만 한 줄씩: `원 — 모양(모서리 둥글림), 획순(1획 반대로 그음)`. 거부 글자는 `풍 — 다시 써 주세요(목표 글자와 다름)` |

- 글자 이름은 내부 id(`char_3`)가 아니라 **목표 글자**를 쓴다.
- 자간은 두 글자 사이 값이므로 뒤 글자에 붙이고, 문구로 방향을 밝힌다: `배치(앞 글자와 너무 좁음)`.
- 박스 색은 축 하나라도 걸리면 빨강(항목별 OR, 지금 규칙 유지). 종합 점수로 색을 정하지 않는다.
- 글자를 탭했을 때의 바텀시트는 유지하고, 문장에서는 거기서 성분 단위 상세를 본다.
- 걸린 세부 판정이 하나도 없고(측정된 축이 전부 100) 거부도 없을 때만 "모든 항목이 기준을 잘 지켰어요"를 띄운다.

## 7. 데이터 계약

### 7.1 AI → 백엔드 (`analyze_canvas_writing` 글자별 결과)

새 필드와 바뀌는 필드:

```
axes: {
  "획순":   {"score": 100 | 70 | 40 | null, "reasons": ["1획 반대로 그음"]},
  "모양":   {...},
  "짜임새": {...},   # 자모음에서는 null
  "배치":   {...}    # 문장에서만, 그 외 null
}
overall_score: int | null        # 4절의 글자 점수. 문장의 거부 글자는 0
scorable: bool
unscorable_reason: "shape_mismatch" | "too_many_strokes" | "missing" | null
failed_items: ["모양(모서리 둥글림)", "획순(1획 반대로 그음)"]   # 축 이름(세부 사유) — 우측 패널 문구 그대로
component_boxes:
  - 자모음: null
  - 한 글자: 성분 박스 목록(지금 형식, failed_items만 축 이름으로)
  - 문장: 글자 박스 1개 [{"block": 0, "jamo": <목표 글자>, "role": "글자", "box": <글자 테두리>,
            "ok": bool, "failed_items": [...]}]
```

유지하는 필드: `char_id`, `stroke_order_result`, `direction_result`, `tilt_result`, `corner_result`, `balance_result`, `char_rotation_deg`, `spacing_deviation`, `size_deviation`, `size_fill_ratio`, `position_result`, `speed_profile`, `correction_flags`, `corrections`, `character_match`(진단용).

없애는 필드: `item_scores`(→ `axes`로 대체). `canvas_item_scores()`는 축 점수를 만드는 함수로 바뀐다.

`correction_flags`의 기록용 진단값(`unscorable:…`, `match_dist:…`, `ink_gap:…`)은 그대로 둔다(화면에는 안 나간다).

### 7.2 백엔드 → 앱

- `CanvasCharAnalysis`: `axes` 추가, `item_scores` 제거, 나머지 7.1과 동일.
- `/feedback`의 `feedback_items[].feedback_message`: 그 글자의 `failed_items`를 `, `로 이은 문자열. 비어 있으면 빈 문자열(화면이 "통과"로 다룬다). 백엔드가 "획순이 정확합니다" 같은 문장을 조립하는 코드는 없앤다.
- `/feedback`의 `overall_score`: 4절의 세션 점수. 자모음·한 글자의 거부 세션만 null.
- `achievement_message`: 점수 구간 문구는 유지(90/70/50). 거부 세션은 "목표 글자와 달라 채점하지 않았어요", 문장에 거부 글자가 섞여 있으면 점수 문구 뒤에 "다시 써야 할 글자가 N자 있어요"를 붙인다.

### 7.3 저장

`canvas_analysis_results`에 **`item_scores JSON` 컬럼**을 추가하는 Alembic 마이그레이션 하나. 값은 `{"획순": 100, "모양": 70, "짜임새": null, "배치": null}` 형태(축 점수만, 사유는 `correction_flags`와 중간 결과로 충분). `overall_score`는 4절의 뜻으로 저장한다.

## 8. 대시보드

- 세션 종합 = 그 세션 행들의 `overall_score` 평균(None 제외). 전부 None이면 세션 제외. (문장의 거부 글자는 0으로 들어가므로 세션은 집계된다.)
- 취약 항목 = 저장된 `item_scores`의 축 4개 평균. 컬럼이 없는 이전 행은 항목 집계에서 빠진다(종합 점수 추세는 유지된다). 이 불연속은 감수한다.
- 대시보드가 중간 결과로 점수를 다시 계산하는 코드(`_canvas_item_scores`)는 없앤다.

## 10. 테스트 전략

- AI: 표준대로 쓴 글씨는 모든 단계에서 100점이고 사유가 없다(연습 글자 전부 + 전체 음절 전수 스크립트). 한 가지 실수 → 해당 축만 70, 두 가지 → 40. 단계별로 측정되는 축이 표와 같다. 거부는 두 조건에서만 일어나고, 획을 이어 쓴 글씨는 거부되지 않는다. 문장에서 한 글자 거부 → 그 글자 0점, 나머지 정상, 문장 점수 = 평균.
- 백엔드: `generate_canvas_feedback`이 사유를 그대로 전달하고 점수를 4절대로 내는지 함수 단위로 확인. 마이그레이션 적용 후 `alembic current`가 head.
- 앱: 모델 테스트(`axes` 파싱, 글자별 사유 묶기), 위젯 테스트(문장 모드에서 글자 박스가 문제 글자 수만큼 그려지고 우측에 같은 수의 줄이 나오는가).
- 실기기: 자모음·한 글자·문장 각 한 번씩 써서 화면 확인.

## 11. 위험과 미결

- 축 점수 70/40의 체감이 맞는지는 실사용 뒤에 알 수 있다. 숫자는 상수 한 곳에 둔다.
- 거부는 획 모양·잉크 두 기준을 함께 쓴다. "비슷한 다른 글자(밤↔방)"는 어느 기준으로도 못 가른다.
- 이전 저장 데이터는 축 점수가 없어 취약 항목 집계에서 빠진다.
- 자리 그룹핑(획이 옆 칸으로 넘어가는 문제)은 이 설계로 해결되지 않는다. 문장에서 거부 글자가 0점이 되면 그 문제가 "채점 불가" 대신 "0점 글자"로 보이게 된다.
